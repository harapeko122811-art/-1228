# GMO「お名前.com デスクトップクラウド」不正アクセス事案（2026年10月）原因分析

- 情報基準日：2026-11-02
- 方法：公開情報（GMO公式発表を伝える報道、技術解説、攻撃者声明を伝える報道）のみに基づくOSINT分析。GMOのシステムへのアクセスや攻撃者との接触は行っていない。
- 確度の表記：**【確定】** GMO公式発表／主要報道で確認、**【主張】** 攻撃者側の声明で未検証、**【推定】** 本分析による技術的推論

## 1. 結論（要旨）

1. **最初の侵入経路はGMOから公式には公表されていない。** GMOは「サービスのシステムにセキュリティ上の問題があった」ことを認めているが、具体的な脆弱性・CVE・マルウェア名は示していない。
2. 攻撃者の声明と状況証拠を合わせると、最も可能性が高い原因は **「顧客VPS群がActive Directoryで一元管理され、全VPS共通の特権アカウントが存在した」という設計上の問題**である【主張＋推定】。特定のソフトウェアの脆弱性（ゼロデイ等）というよりは、**構成・運用上の不備（信頼境界の欠如）** と見るのが妥当。
3. 想定される攻撃の流れ【主張＋推定】：
   1. 攻撃者が正規に契約した（または入手した）VPSを足場にする
   2. 保守担当者がRDPで接続した際にVPS上に残った**管理者の認証情報をメモリから窃取**（Windowsの資格情報キャッシュ、Mimikatz系の手口）
   3. その**共通管理者権限でAD配下の他の顧客VPSへ横展開**
   4. 各VPSに保存されたFX取引口座のログイン情報を取得し不正取引、顧客情報を外部へ持ち出し
   5. **RDPのドライブリダイレクト（ドライブ共有）** 経由で利用者の手元PCのファイルにも到達したと主張
4. 同時期に報じられたGMOグループ別会社の「GMOトラスト・ログイン」の4.5万人分漏えいは、**別の事案**。原因は公開ストレージへの個人情報ファイルの誤配置で、約9年間外部から取得可能だった【確定】。

## 2. 事実関係（時系列）【確定】

|---|---|
| 10/19 | 顧客の問い合わせを受けて調査開始 |
| 10/20 | 一部の顧客サーバーに不正なプログラムが置かれたことを確認 |

| 10/27 | 第8〜10報。正午の「攻撃予告」前に利用者へバックアップ・ネットワーク切断・電源断を要請。攻撃者が顧客情報を公開。ランサムウェア被害は確認されずと発表 |

- 影響対象：最大26,739件のサーバー。これは「侵害が確認された数」ではなく「影響が懸念される基盤の総数」。
- 被害：サーバー内に保存された取引口座のログイン情報が取得され、一部FX口座で身に覚えのない取引。
- GMOは身代金の支払いを拒否。サービスは再開しない方針と報じられている。

## 3. 原因の技術分析

### 3.1 攻撃者が挙げた不備【主張】
- VPSネットワークがActive Directoryで構成され、VPSから別のVPSへ移動できる経路があった
- すべてのVPSに管理者権限を持つ共通アカウントが存在した
- 保守担当者がRDPで顧客VPSに接続した際、管理者の認証情報がメモリに残り窃取できた
- RDPのドライブリダイレクトで利用者PCのファイルを読めた
- 解約済みのサーバーが残っていた

### 3.2 評価【推定】
- この主張は、**「被害が単一顧客ではなく多数のVPSに同時に広がった」「VPS上の口座情報が狙われた」** という確定事実と整合する。個別のVPSが一台ずつ破られたのなら、ここまで短期間に広がりにくい。共通の管理面（AD／共通特権）を握られたと考えると説明がつく。
- RDPで特権アカウントがログオンすると、接続先に資格情報が残る（LSASS上の認証情報）のはWindowsの既知の性質。対策として Restricted Admin モード、Remote Credential Guard、Protected Users グループ、Tier モデルによる特権分離がある。これらが使われていなかった可能性が高い。
- マルチテナント環境で**顧客同士を同じADドメインに入れ、共通の管理者アカウントを使う**のは、テナント間の信頼境界がない状態。1台の侵害が全台の侵害につながる。
- 「最初の足場」は、攻撃者が自分で正規契約したVPSという説が出ている。そうであれば、外部からの脆弱性悪用は不要で、**サービスを契約できる者なら誰でも内側に入れた**ことになる。
- PHPの脆弱性や特定マルウェア（ARTEX等）との関連は、いずれも根拠が示されておらず、現時点では採らない。

### 3.3 根本原因（まとめ）【推定】
| 層 | 問題 |
|---|---|
| 設計 | テナント分離の欠如（顧客VPSを共通ADドメインで管理、共通特権アカウント） |
| 運用 | 保守時のRDP接続で特権資格情報を顧客環境に残す手順 |
| 設定 | RDPドライブリダイレクトの許可、解約済み環境の残存 |
| 検知 | 横展開と大量の情報持ち出しを初期段階で検知できなかった（発覚は顧客の問い合わせ） |

## 4. 別事案：GMOトラスト・ログイン（GMOグローバルサイン）【確定】
- 2,492社・45,030人分（氏名、メールアドレス、連携サービス名、社員番号など。パスワード・多要素認証情報・決済情報は含まず）
- 原因：ロゴ画像などを公開するストレージに、個人情報を含むファイルを保管していた設定不備
- 期間：2017年11月〜2026年9月（約9年）。少なくとも2021年6月以降に第三者の取得を確認
- 発覚：外部のセキュリティ研究者の指摘。定期診断・侵入テストの対象外だった

## 5. 利用者が取るべき対応
1. デスクトップクラウド上に保存していたFX口座などのID・パスワードをすべて変更し、多要素認証を有効にする
2. 取引履歴・出金先の登録情報に不審な変更がないか確認する
3. デスクトップクラウドへRDPで接続していた手元PCは、ウイルススキャンを行い、同じPCに保存していた認証情報も変更する
4. `.rdp` ファイルのドライブ共有設定を無効にする（今後ほかのVPSでも）
5. 「被害者救済」をうたう不審なサイトや連絡に情報を入力しない（攻撃者関連とみられる不審サイトが報じられている）

## 6. 未解明事項
- 最初の侵入の正確な経路（正規契約VPSか、別の外部公開部分か）
- 侵害が確認された実際の台数と、持ち出された情報の総量
- 攻撃者の主張がGMOの調査結果とどこまで一致するか

公式の最終報告が出た時点で、本分析を更新する必要がある。
